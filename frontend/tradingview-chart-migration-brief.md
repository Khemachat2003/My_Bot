# Migration Brief: เปลี่ยนกราฟจาก Canvas มือเขียน → lightweight-charts (TradingView)

แนบพร้อม 2 ไฟล์ demo: `tradingview-style-chart-demo.html` (กราฟราคา + marker + SL/TP + S/R) และ `equity-curve-demo.html` (equity curve) — เปิดดูได้ตรงในเบราว์เซอร์ ทั้งสองไฟล์รันได้จริงด้วยไลบรารีจริง ไม่ใช่ mockup ภาพนิ่ง

---

## ต้องติดตั้งอะไรเพิ่ม

```bash
npm install lightweight-charts
```
ไลบรารีนี้คือ **TradingView เขียนเองและปล่อยเป็น open source (Apache 2.0 license) ฟรี** ใช้ในโปรดักชันได้ นี่คือ engine กราฟตัวเดียวกับที่ขับเคลื่อนกราฟบนเว็บ TradingView บางส่วน (ไม่ใช่ตัวเต็มของเว็บ TradingView แต่เป็น charting engine หลัก) — เพราะฉะนั้นการขอให้ "หน้าตาเหมือน TradingView มากที่สุด" คำตอบที่ตรงที่สุดคือใช้ของจริงจากเจ้าของเลย ไม่ใช่พยายามเลียนแบบด้วย canvas เอง

ถ้าไม่ได้ใช้ bundler (webpack/vite) ในโปรเจกต์นี้ ใช้ผ่าน CDN แทนได้ (ตามที่ demo ทำ):
```html
<script src="https://unpkg.com/lightweight-charts@4.1.3/dist/lightweight-charts.standalone.production.js"></script>
```

**สำคัญ**: เปลี่ยนแค่ "เครื่องมือวาดกราฟ" ไม่เปลี่ยน backend/logic คำนวณสัญญาณ/SL/TP ใดๆ ทั้งสิ้น — เดิม backend ส่ง JSON มา (OHLC, entry, sl, tp1, tp2, ระบบที่ยิงสัญญาณ) เท่าที่มีอยู่แล้ว แค่เปลี่ยนวิธี "วาด" จาก `ctx.fillRect/ctx.arc` มือเขียน เป็นเรียก API ของ `lightweight-charts` แทน

## ข้อ 1: Equity Curve ให้ชัดกว่าเดิม

ปัญหาเดิม (สันนิษฐานจากที่ระบบ chart มือเขียนทั้งหมด): แกน x/y ไม่ได้ label ความหมายชัด, ไม่มี format หน่วยเงิน, มองยากว่าค่าปัจจุบันเทียบกับทุนตั้งต้นเท่าไหร่

ทำตาม `equity-curve-demo.html`:
- ใช้ `chart.addAreaSeries()` พร้อม `priceFormat` custom formatter ใส่ `$` และ comma คั่นหลักพันให้แกน y เสมอ (ไม่ใช่ตัวเลขลอยๆ)
- ใส่ `series.createPriceLine()` เป็นเส้นประที่ระดับ "ทุนเริ่มต้น" ให้เห็นทันทีว่าตอนนี้อยู่เหนือ/ใต้จุดเริ่มต้นเท่าไหร่
- แกน x ใช้ `time` เป็น timestamp จริงของแต่ละวัน (ไม่ใช่ index ลำดับเทรดที่ 1,2,3...) เพื่อให้เห็นว่าช่วงไหนกำไรโตเร็ว/ช้า
- แสดง stat สรุป (ยอดปัจจุบัน, กำไรสุทธิ, Max Drawdown, จำนวนเทรด) เป็นตัวเลขแยกด้านบนกราฟ ไม่ต้องอ่านจากกราฟเอาเอง
- Native hover tooltip + zoom/pan ได้ทันทีจากไลบรารี ไม่ต้องเขียนเอง

## ข้อ 2: ตัวบอกจุดเข้า ไม่ชัดว่าแท่งไหน/ทิศไหน/ระบบไหน + SL/TP ปนกันหลาย trade

ทำตาม `tradingview-style-chart-demo.html`:

### หลักการ encode ข้อมูล
- **รูปทรง marker = ทิศทาง**: ลูกศรชี้ขึ้น (`arrowUp`) = CALL/BUY, ลูกศรชี้ลง (`arrowDown`) = PUT/SELL — วางด้วย `series.setMarkers([{time, position, shape, color, text}])` ซึ่งผูกกับแท่งเทียนที่ระบุแม่นยำ 100% ไม่มีปัญหา "ไม่รู้แท่งไหน" อีกต่อไป เพราะ marker ยึดกับ `time` ของแท่งนั้นโดยตรง
- **สี marker = ระบบต้นทาง**: ML = ม่วง `#9C6FE0`, Rule-based/IMP1/IMP2 = น้ำเงิน `#2962FF` (หรือแยกเฉดต่อ IMP level ถ้าต้องการ) — แก้ปัญหา "ไม่รู้ว่าระบบไหนยิงสัญญาณ" เพราะสีคงที่ต่อระบบเสมอ ไม่ปนกับสี bull/bear ของแท่งเทียน
- ข้อความบน marker ใส่ทั้งชื่อระบบ+ทิศทาง (เช่น "IMP1 PUT") สั้นๆ ให้อ่านออกทันทีโดยไม่ต้องคลิก

### SL/TP ไม่ปนกันข้าม trade (ประเด็นเรื่อง CFD ที่เข้าจุดเดียวกับ IMP1)
ของเดิมน่าจะวาดเส้น SL/TP ของทุก trade ค้างไว้พร้อมกันหมด ทำให้รกเมื่อมีหลาย trade ซ้อนกัน — **TradingView เองก็ไม่แสดงทุก position พร้อมกันตลอดเวลาเช่นกัน** (ใช้เครื่องมือ "Long/Short Position" ทีละอันที่ผู้ใช้เลือกดู) ให้ทำตามแบบนั้น:
- มี trade list (รายการที่มีอยู่แล้วในระบบ) ให้คลิกเลือกทีละแถว
- เมื่อเลือก 1 trade: เรียก `series.createPriceLine()` วาด 4 เส้น (Entry/SL/TP1/TP2) ของ trade นั้นเท่านั้น
- เมื่อเลือกแถวใหม่: ต้อง `series.removePriceLine()` ของเส้นชุดเก่าทั้งหมดก่อน แล้วค่อยวาดชุดใหม่ (ดูฟังก์ชัน `showTrade()` ใน demo)
- ผลลัพธ์: ไม่ว่าจะมี trade ซ้อนกันจากจุดเข้าเดียวกันกี่รายการ กราฟจะโล่งอยู่เสมอ เห็นแค่ SL/TP ของรายการที่กำลังดูอยู่จริง
- ถ้าอยากให้ position ที่ **กำลังเปิดอยู่จริง (live)** ต่างจาก historical ที่ปิดไปแล้ว ให้ set default เลือกแสดงเฉพาะ open position อัตโนมัติตอนโหลดหน้า ส่วน historical ต้องกดเลือกเองถึงจะเห็น

## ข้อ 3: Layout ทั้งชุดอิง TradingView + มือถือซูม/เลื่อนได้ + วาดเส้น S/R เอง

- `lightweight-charts` รองรับ **pinch-zoom และ pan ด้วยนิ้วบนมือถือ, scroll wheel/drag บนเดสก์ท็อป โดยอัตโนมัติ** ไม่ต้องเขียน touch event เอง แก้ปัญหา "มือถือซูม/เลื่อนไม่ได้" ทันทีที่เปลี่ยนมาใช้ไลบรารีนี้
- แบ่งกราฟเป็น 2 pane ซ้อนกันแบบ TradingView: กราฟราคาหลัก (candlestick) + pane เล็กด้านล่างสำหรับ volume/indicator (`addHistogramSeries`) — sync การ zoom/pan สองกราฟให้ตรงกันด้วย `subscribeVisibleLogicalRangeChange` (โค้ดใน demo ทำไว้แล้ว)
- Legend มุมซ้ายบนแสดง OHLC ของแท่งที่ crosshair ชี้อยู่ ผ่าน `chart.subscribeCrosshairMove()` — นี่คือแพทเทิร์นเดียวกับที่ TradingView ใช้จริง
- **เส้น S/R ที่ผู้ใช้เพิ่มเอง**: กดปุ่ม "เพิ่มเส้น S/R" → คลิกจุดบนกราฟ → อ่านราคาที่จุดนั้นด้วย `series.coordinateToPrice(y)` → สร้างเส้นด้วย `createPriceLine()` → เก็บ reference ไว้ใน list ที่ลบออกได้ทีหลัง (ดูส่วน `srPanel` ใน demo)
  - ถ้าต้องการเส้น S/R ที่ **ลากปรับตำแหน่งได้ทีหลังด้วยเมาส์** (ไม่ใช่แค่ลบแล้ววางใหม่) ต้องใช้ปลั๊กอินเสริมนอกเหนือจากไลบรารีหลัก เช่น community plugin `lightweight-charts` drawing-tools (มีให้ค้นหาบน GitHub/npm หลายตัว เพราะ v4 ของไลบรารีเปิด plugin API ให้ทำได้) — แนะนำให้เริ่มจากแบบ "คลิกวาง/กดลบ" ตาม demo นี้ก่อน เพราะครอบคลุม use case หลักแล้ว ค่อยเพิ่ม drag ทีหลังถ้าจำเป็นจริง

## ข้อ 4: ไอคอน ห้ามใช้ emoji

ใน demo ใช้ inline SVG (Feather-icons style) ตรงๆ ไม่มี dependency เพิ่ม แต่ถ้าต้องใช้ไอคอนเยอะทั้งระบบ แนะนำติดตั้งชุดไอคอนจริงแทนการ hand-draw SVG ทีละอัน:

```bash
npm install @tabler/icons
```
(หรือใช้ผ่าน CDN `<link>` webfont ก็ได้ถ้าไม่อยาก build) ชุดนี้มีไอคอนกว่า 5,800 แบบ outline สื่อความหมายตรงตัว เช่น ลูกศรขึ้น/ลง, กระดิ่งแจ้งเตือน, เฟืองตั้งค่า, กราฟแท่ง ใช้แทน emoji ได้ครบทุกจุดที่เคยมี 📈📊🤖⚙️

## ข้อ 5: Theme ยังดู "AI ทำ" อยู่ — อ้างอิงจาก TradingView จริงแทนการคิดเอง

ค่าสีที่ใช้ใน demo ทั้งสองไฟล์ **คือค่าที่ตรงกับธีมมืดจริงของ TradingView** (เป็นตัวเลข hex ทั่วไป ไม่ใช่ความลับทางลิขสิทธิ์อะไร ใช้ประกอบ UI ได้ปกติ):

| Token | ค่า | ใช้ทำอะไร |
|---|---|---|
| พื้นหลัง | `#131722` | กราฟิกไม่มี tint ไล่สีใดๆ |
| grid line | `#1E222D` / `#2A2E39` | เส้นตารางบางมาก แทบไม่สังเกตเห็น |
| ตัวหนังสือรอง | `#787B86` | เทากลาง ไม่ขาวจ้า ไม่ดำสนิท |
| แท่งขึ้น | `#26A69A` | เขียวอมฟ้า (teal) ไม่ใช่เขียวสดจัด — จุดสำคัญ: TradingView **ไม่ใช้เขียวจัด/แดงจัดแบบ neon** เหมือน dashboard ทั่วไป สีนุ่มกว่ามาก |
| แท่งลง | `#EF5350` | แดงอมส้มนุ่มๆ ไม่ใช่แดงเลือดจัด |
| accent เดียว | `#2962FF` | ใช้เฉพาะปุ่ม/สถานะ active เท่านั้น |

จุดที่ทำให้ของเดิมดู "AI ทำ" คือใช้สีเข้มจัด/สดจัดเกินไป (สีที่ค่า saturation สูง เช่น `#22c98a` เขียวสดมาก) ในขณะที่ TradingView ตั้งใจลด saturation ลงเสมอเพื่อให้มองนานๆ ไม่ล้าตา — นี่คือหลักการที่ควรยึดทั้งระบบ ไม่ใช่แค่ในกราฟ: **ทุกสีในทั้งแอป ลด saturation ลงจากที่เคยทำไว้ก่อนหน้านี้ทั้งหมด (รวมถึงชุดสีที่ผมเคยให้ไปตอนแรก `#16C784`/`#F0465C` ก็ยังจัดไปเมื่อเทียบกับของจริง) ให้เปลี่ยนไปใช้ค่าตารางด้านบนแทนทั้งระบบเพื่อความสอดคล้อง**

Layout hierarchy: ให้ยึดหลักที่คุยกันไปก่อนหน้า (กราฟใหญ่เป็นพระเอก, stat เป็นแถบไม่ใช่การ์ด, hairline แทน box) ร่วมกับชุดสีนี้

## สรุปสิ่งที่ opencode ต้องทำ

1. `npm install lightweight-charts` (หรือ CDN ถ้าไม่มี build step) และ `npm install @tabler/icons` (หรือ CDN)
2. เขียนฟังก์ชันวาดกราฟราคาใหม่ทั้งหมดด้วย `lightweight-charts` แทนโค้ด canvas เดิม โดยอ่านข้อมูล OHLC/marker/SL-TP จาก API เดิมที่มีอยู่แล้ว (ไม่แก้ backend)
3. ทำ trade-list-click-to-highlight ตามที่อธิบายในข้อ 2 (แก้ปัญหา SL/TP ปนกัน)
4. เปลี่ยน Equity Curve เป็น `addAreaSeries` ตามที่อธิบายในข้อ 1
5. แทนที่ emoji ทั้งหมดด้วย Tabler icons
6. อัปเดตชุดสีทั้งระบบเป็นค่าตามตารางข้อ 5 (แทนที่ชุดสีที่ให้ไปก่อนหน้านี้ทั้งหมด)
7. ทดสอบบนมือถือจริงว่า pinch-zoom/pan ใช้ได้ และ marker/SL-TP อ่านง่ายในจอเล็ก
